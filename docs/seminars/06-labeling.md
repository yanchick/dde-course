# Семинар 6 — Системы разметки и аннотации

**Связанная лекция:** [Системы разметки и аннотации данных](../lectures/05-labeling.md)

## Цель

Понять разметку как инженерный процесс, а не как «люди проставят метки».
Собрать LS-совместимый проект, выбрать задачи активным обучением, измерить
согласие аннотаторов через Cohen's kappa, выгрузить аннотации в озеро и
проверить, что разметка действительно улучшает модель.

Label Studio в стенде нет: это backlog SRV-15 (поднять LS) и SRV-16
(отправка задач через `/api/projects`). Семинар не требует Docker и строит
тот же JSON локально — позже он уходит в настоящий LS без переделки.

## Результаты

- Студент собирает проект разметки в формате Label Studio: XML-конфиг с
  тремя классами и 100 задач без меток.
- Выбирает 15 из 100 отзывов активным обучением: неуверенность плюс штраф
  за ноль попаданий лексикона; проверяет, что это 15% бюджета.
- Считает agreement и Cohen's kappa без sklearn, объясняет интерпретацию
  по Landis & Koch и почему kappa строго меньше процента согласия.
- Экспортирует 100 аннотаций в LS-JSON; при живом MinIO — в
  `lake/labels/reviews/{dt}/annotations.json`, иначе — локально.
- Учит лексикон на 60 отзывах и показывает прирост на 40 тестовых
  (baseline `0.6500` → learned `0.8750`, `delta +0.2250`).
- Разбирает кейс 40% разногласий: какие классы спорят и что с этим делать.

## Задания

1. **6.1 Проект разметки.** `build_labeling_project`: title, `LABEL_CONFIG`
   (`<Text name="text">` + `<Choices name="sentiment" choice="single">`)
   и 100 задач с `id` и `data.text/review_id/dataset_id`. Проверка:
   100 задач, уникальные id, непустые тексты, ровно 3 `<Choice>`.
2. **6.2 Активное обучение.** `select_for_labeling`: неуверенность
   `1 − min(1, |score|)` плюс `1.0` при `hits == 0`, сортировка
   `(−uncertainty, review_id)`. Проверка: 15 уникальных задач, 15% < 20%,
   минимум 5 без попаданий лексикона, `MANUAL_SEED` заполнен.
3. **6.3 Cohen's kappa.** `agreement_report` на паре «аннотаторов» с
   6 и 7 флипами: agreement, kappa, интерпретация, расхождения. Проверка:
   `n=40`, `kappa ≥ 0.6`, `kappa < agreement`, число расхождений сходится.
4. **6.4 Экспорт.** `export_annotations`: валидация трёх классов, LS-JSON
   (`from_name`, `to_name`, `type`, `value.choices`), запись в MinIO через
   boto3 с `connect_timeout=2` и одной повторной попыткой, fallback в
   `LABELS_OUT`. Проверка: 100 записей, `schema_ok`, `stored ∈ {minio, local}`.
5. **6.5 Разметка → признаки.** `evaluate_labeling_impact`: лексикон на
   первых 60 отзывах, оценка на последних 40, сравнение с фиксированным
   `score_text`. Проверка: `learned ≥ baseline`, `delta ≥ 0.05`.

## Эксперимент

Две разметки одного и того же: A — истина, B — истина с 16 флипами по
чётным индексам. Disagreement ровно `0.4`, kappa `0.3887` — «слабое».
Студент собирает `analyze_conflicts`: разбивку по классам и три примера
спора. Обсуждаем, что делать при 40%: перечитать инструкцию, арбитраж
третьим экспертом, обновить гайдлайны, добавить класс «неуверен» или
объединить метки; иногда виноват один выбивающийся аннотатор.

## Как запускать

### Подготовка стенда

```bash
git clone https://github.com/yanchick/Sputnik-Mart.git ~/Sputnik-Mart
cd ~/Sputnik-Mart
uv sync --all-packages --dev
```

!!! info "Docker не нужен, Label Studio в стенде нет"
    В `docker-compose.yml` репозитория **нет сервиса Label Studio**: это
    backlog-задачи **SRV-15** (поднять LS в профиле `adv/demo`) и **SRV-16**
    (отправлять задачи в LS через `POST /api/projects`). Семинар не изображает
    живой LS API: он строит **LS-совместимые** project/tasks/export JSON
    локально. Тот же payload позже уходит в настоящий LS без переделки.

    Достаточно venv репозитория: `transform.gold_sentiment`, `boto3` и стандартная
    библиотека. Задания 6.1–6.3, 6.5 и эксперимент — чистые вычисления; 6.4
    пишет в MinIO, а при его отсутствии — в локальную папку.


### Запуск из терминала

```bash
export SPUTNIK_REPO=~/Sputnik-Mart
# из корня репозитория
cd "code/seminars/06_labeling"

# студенческая версия (все 7 проверок FAIL до выполнения заданий — это ожидаемо)
uv run --project "$SPUTNIK_REPO" python seminar_06.py

```

`--with` не нужен: `boto3` уже есть в окружении репозитория. Если его нет,
добавьте `--with boto3` — без пакета экспорт уйдёт в локальный fallback.

!!! note "Скрипт импортирует код репозитория"
    Без `--project "$SPUTNIK_REPO"` (или вне venv репозитория) не разрешится
    `transform.gold_sentiment`.


### Запуск в JupyterLab

```bash
cd ~/Sputnik-Mart
uv run jupyter lab
```

Откройте `seminar_06.py` как notebook (JupyterLab понимает percent-format).
Выполняйте ячейки сверху вниз. Переменные `CORPUS`, `QUEUE`, `KAPPA_REPORT`,
`EXPORT_RESULT`, `IMPACT` и `CONFLICT_REPORT` объявлены в блоке «Прогон»,
поэтому ячейки можно запускать повторно.

### Переменные окружения

| Переменная         | По умолчанию            | Зачем                                      |
| ------------------ | ----------------------- | ------------------------------------------ |
| `SPUTNIK_REPO`     | — (только для uv --project) | путь к Sputnik-Mart для команды запуска |
| `SEED`             | `42`                    | детерминизм корпуса и флипов               |
| `N_REVIEWS`        | `100`                   | размер корпуса                             |
| `ACTIVE_BUDGET`    | `15`                    | сколько задач брать в активное обучение    |
| `LABELS_OUT`       | `./_out/labels`         | куда писать экспорт при недоступном MinIO  |
| `EXPORT_DT`        | `2026-10-01`            | партиция даты в ключе экспорта             |
| `MINIO_ENDPOINT`   | `http://localhost:9000` | S3-совместимый endpoint                    |
| `MINIO_ACCESS_KEY` | `sputnik`               | ключ MinIO                                 |
| `MINIO_SECRET_KEY` | `sputnik123`            | секрет MinIO                               |
| `MINIO_BUCKET`     | `lake`                  | бакет озера                                |

Константы `N_TRAIN`, `N_TEST`, `KAPPA_N`, `KAPPA_FLIPS_A`, `KAPPA_FLIPS_B`,
`CONFLICT_N`, `CONFLICT_FLIPS` задаются через env, по умолчанию: `60`, `40`,
`40`, `6`, `7`, `40`, `16`; это части условия, менять их без необходимости
не нужно.

### Ожидаемый результат

1. **Корпус.** Банк: 30 positive + 30 negative + 30 нейтральных
   (5 стартовых + 25 обычных) + 10 трюков.
   После перемешивания и добавления трюков — 100 отзывов, 5 датасетов.
   Оракул симуляции: `positive=31, negative=37, neutral=32` (трюки добавляют
   к базовым 30/30/30 ещё 1 positive, 7 negative и 2 neutral). Первые пять
   отзывов — `rv_0001`…`rv_0005`, все нейтральные и без попаданий лексикона.
2. **6.1.** Проект: 100 задач, `id` 1..100, у каждой непустой `data.text`,
   `review_id`, `dataset_id`; в `label_config` три `<Choice>` и
   `name="sentiment"`. Первая задача:
   `{"id": 1, "data": {"text": "Скачал, посмотрю позже.", "review_id": "rv_0001", "dataset_id": "ds_weather-stations"}}`.
3. **6.2.** Предразметка — 100 строк; очередь — `15` из `100` (`15%`),
   все 15 без попаданий лексикона; первые пять — `rv_0001`…`rv_0005`;
   `MANUAL_SEED` заполнен на `5/5`.
4. **6.3.** `agreement=0.8250` (33 из 40), `kappa=0.7363`,
   интерпретация «существенное», расхождений `7`.
5. **6.4.** `count=100`, `schema_ok=True`. В прогоне без MinIO —
   `stored="local"`, ключ `lake/labels/reviews/2026-10-01/annotations.json`,
   файл `_out/labels/2026-10-01/annotations.json`. Если MinIO поднят,
   `stored="minio"` и тот же ключ в бакете `lake`.
   Экспорт использует оракул симуляции `SIM_LABELS`; в реальном проекте метки
   приходят от аннотаторов/LS.
6. **6.5.** `n_train=60`, `n_test=40`; baseline `0.6500`, learned `0.8750`,
   `delta=+0.2250`; в выученном лексиконе `36` слов, ошибок после — `5`.
   Три ошибки в консоли: `rv_0073` (neutral → positive), `rv_0081`
   (positive → neutral), `rv_0082` (neutral → positive).
7. **Эксперимент.** `disagreement=0.4000`, `kappa=0.3887`; по классам
   positive `a=9, b=11, disagreements=8`, negative `a=15, b=10,
   disagreements=11`, neutral `a=16, b=19, disagreements=13`; три примера
   с `A ≠ B`.
8. Итог: `Итог: 7/7 проверок пройдено`.

!!! note "Почему 60/40, а не 50 размеченных"
    100 отзывов делятся на 60 train и 40 test: так в тесте остаются все
    10 намеренно трудных случаев (они стоят в конце корпуса), и прирост
    измеряется на честном hold-out, а не на тех же примерах, что учили.


!!! note "MinIO может быть выключен"
    В прогоне, на котором сняты числа выше, `localhost:9000` не отвечал,
    поэтому `stored="local"`. Это штатный сценарий: проверка допускает и
    `minio`, и `local`. Поднимать весь `docker compose` ради 6.4 не нужно.


!!! note "«Ошибок нет, всё отлично» — не ошибка лексикона"
    Основа `ошибк` не является подстрокой слова `ошибок`, поэтому
    фиксированный лексикон видит только `отличн` и ставит positive. Ответ
    верный, но по случайности — хороший повод обсудить, что accuracy не
    отличает понимание от везения.


### Если что-то не работает

| Симптом                                             | Что делать                                                                 |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| `ModuleNotFoundError: transform`                    | запускать через `uv run --project "$SPUTNIK_REPO"`                         |
| 6.4: `Connection refused` на 9000                   | это нормально: MinIO выключен, экспорт ляжет в `LABELS_OUT/{dt}/`. Проверьте `stored="local"` |
| 6.4: `stored="minio"`, но файла нет локально        | так и должно быть: объект в бакете `lake`, ключ печатается в консоли        |
| Порт 8080 отвечает, но это не Label Studio          | на 8080 — **Redpanda Console**, LS в стенде нет (SRV-15)                    |
| `boto3` не установлен                               | `uv run --with boto3 ...` или `uv sync --all-packages --dev`; без пакета будет local |
| 6.3: kappa ниже 0.6                                 | проверьте, что флипы A и B не пересекаются и что корпус собран с `SEED=42`  |
| 6.2: очередь пустая                                 | `budget` должен быть > 0; `preannotate` не должен возвращать пустой список  |
| 6.5: `delta < 0.05`                                 | не меняйте тестовую часть и не подмешивайте её в train; проверьте, что `SIM_LABELS` от `SEED=42` |
| Кириллица в консоли ломается                        | `export PYTHONIOENCODING=utf-8`                                            |
| Студенческая версия печатает `0/7`                  | это ожидаемо до выполнения заданий; смотрите строки `Задание 6.x не выполнено` и `Эксперимент не выполнен` |
